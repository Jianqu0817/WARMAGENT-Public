# 音乐互动场景：一起挑一首，再聊聊 · 仅规划

本轮不安装、登录或控制播放器。先验证已有客户端再选适配器；可优先评估网易云桌面版，客户端与接口支持尚未确认，不视为现有能力。

## 首版体验

1. 你说“想听点什么”，小温暖结合当前聊天、已知兴趣，提出一首或一个方向，也可以说今天没有合适推荐。
2. 通过工具确认当前曲目和播放状态，选曲后实际播放，再核对状态。没有可用客户端时给曲目链接，不能声称已经播放。
3. 你随时换曲、暂停、表达喜好。小温暖自然回应；没有话说时保持安静，不逐曲写总结。
4. 小温暖自主时间也可听歌、暂存候选与感受；仅在相关聊天或确有分享意愿时提起，沿用现有省费/打扰规则。

首版提供选曲、播放状态和交流。真正双端同步“一起听”留到后续，须确认平台原生功能和双方连接；本地播放器在播放不证明你的另一台设备正在同步听。

## 最小工程切片

| 拟议接口，未实现 | 返回与核验 |
| --- | --- |
| music_state | 曲目ID、标题、歌手、链接、播放状态、客户端/设备、观察时间；不可读时明确unavailable |
| music_lookup | 按歌名/歌手查找少量候选，返回可核对的曲目ID与链接，不靠模型编歌曲元数据 |
| music_control | 按已确认曲目ID播放，或暂停/继续；提交不等于成功，随后查询状态验证 |

- 适配器接入现有DirectHarness、稳定owner授权、动作锁、调用ID与unknown账本，不开新执行Agent。群友可以聊推荐，设备控制沿用原授权。
- 优先评估客户端可稳定读取的接口；只能走界面时，复用观察/动作/核验，不复制固定模块号或长坐标宏。
- 当前一起听的意图/曲目/反馈引用放既有活动protocol或工作视图，感受存已有随笔；不建音乐专用记忆库或独立人格。
- 不加LLM定时轮询。先按用户请求查询；后续如需状态事件，客户端事件或本地采样只更新状态，不能每次切歌都调用模型。
- 播放超时按unknown处理，先查当前曲目再决定后续动作，避免重复切歌；用户暂停/停止优先于自主续做。

## 验收与后续

先用假播放器贯通：候选→选曲→状态确认→你反馈→下次相关聊天取回感受。再在用户选定的本机客户端做一次只读检查与授权播放/暂停验证。核对模型调用数、工具步骤、核验结果及重复切歌情况；无新固定唤醒费用。

首版完成后再评估平台原生同步听歌、收藏与歌单；QQ空间、自动发布听歌动态不包含在本场景中。实际选客户端和接入接口时再核对当前版本、安装情况与稳定性。
