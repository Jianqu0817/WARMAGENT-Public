# WARMAGENT：把连续性写进底层

WARMAGENT 的技术主线很明确：同一个主脑，持续积累经历，直接使用工具，在聊天、行动、探索与休息之间接续自己的状态。记忆、调度、工具协议和投递回执共同支撑这种连续性。

## 1. 经历有来源，更正有版本

权威档案保存原始消息、事件、解释、摘要、主题及状态。`ID@revision` 固定版本，`source_refs` 与 `source_spans` 指向原话与具体引文位置。修订保留历史，也让新结论有可追查的变化过程。

ArchiveStore 使用跨进程单写者、manifest-last 发布、内容完整性检查、CAS 版本检查与幂等提交。发布后的 manifest 决定可见记录；SQLite 与索引是可重建投影。读取返回独立副本，写入通过权威档案完成。

实现：[archive.py](../src/myatri/storage/archive.py)。夹具：[档案读取与恢复](../tests/test_perf_archive.py)、[记忆质量](../tests/test_memory_quality.py)。

## 2. 混合检索，用多条线索定位同一段经历

每次检索先固定快照和可见范围，再组合以下通道：

| 通道 | 方法 | 擅长的线索 |
| --- | --- | --- |
| 中文全文 | SQLite trigram FTS | 原话片段、名称、术语 |
| 档案词面 | 双字符片段覆盖率，完整匹配加分 | 短查询、原文匹配、索引回退 |
| 向量 | 本地BGE；不可用时使用字符1—4 gram TF-IDF | 换一种表达寻找相关内容 |
| 多视图 | event / feeling / theme / temporary_state | 事件、感受、主题和未结束的意图 |
| 时间与人物 | 显式过滤与已有身份线索 | 指定日期、成员和经历范围 |
| 主题成员 | 相似图、Leiden聚类与主题材料 | 找到同一话题下的一组经历 |

主路径使用RRF融合排序：

```text
score(record) = Σ 1 / (60 + rank_in_channel)
```

排名融合让不同尺度的检索信号共同参与。算法相似度负责寻找候选，事实解释继续依靠来源、归属与更正记录。

本地BGE实现为锁定版本的`bge-small-zh-v1.5`，采用ONNX INT8、512维CLS表示与L2归一化；精确余弦搜索通过NumPy矩阵计算。向量空间同时校验模型、版本、维度与归一化方式。BGE输入上限为512个token；词面通道和精确原文读取覆盖完整存档。

实现：[RecallService](../src/myatri/retrieval/service.py)、[MemoryIndex](../src/myatri/memory/index.py)、[本地BGE](../src/myatri/providers/local_onnx.py)、[精确向量搜索](../src/myatri/memory/vector_index.py)。

## 3. 联想有路径，反证有位置

图结构区分算法相似边与带来源的语义边。主检索从前4个起点做深度1、最多20节点的有界扩展，并补充已有contradicts关系对应的反证材料。真实Leiden聚类生成暂定主题，主题维护拆分、合并与延续关系。

`RecallBundle`携带记录、召回原因、关联路径、反证引用、快照和索引水位。命中事件时优先携带直接原文；更长的来源链保留版本指针，模型可继续展开。

独立的`retrieval_wave`提供按scope限界的传播实验开关，默认关闭；README所述主路径为RRF＋有界图扩展。

实现：[图关系](../src/myatri/memory/graph.py)、[Leiden](../src/myatri/memory/clustering.py)、[主题延续](../src/myatri/memory/themes.py)、[实验传播](../src/warmagent/retrieval_wave.py)。

## 4. 共享经历，保留说话人与场景

GroupRecall把第一人称问题关联到当前稳定账号，并在当前群身份记录内解析明确名字。MemoryVisibility沿来源链检查原文、衍生解释和回复关系，让群聊保持自己的材料范围；本人私聊按部署授权延续共享经历。

搜索目录和原文读取分开。`recall`返回有界目录与摘录，`read_record`读取精确版本并记录字段、区间与未读进度。模型可以凭已有片段回答，也可以继续查证。

实现：[GroupRecall](../src/warmagent/group_memory.py)、[可见范围](../src/warmagent/shared_runtime.py)、[读取协议](../src/warmagent/tool_reading.py)。

## 5. 新经历继续写，索引在后台追上

增量索引组合已验证base与当前delta，默认30秒合并窗口，完整构建在独立本地进程进行。持久向量缓存按文本、视图和模型空间隔离；代际校验与原子current发布保持索引身份和水位一致。

固定本地阶段使用已验证read_view，多个查询共用一个截止点。它把重复的全库检查与复制，收敛为一次入口验证、索引访问与所需结果复制。严格独立读取仍执行原有完整性路径。

实现：[增量索引](../src/warmagent/incremental_index.py)、[向量缓存](../src/warmagent/embedding_cache.py)、[只读阶段](../src/myatri/storage/archive.py)、[精确构图](../src/warmagent/index_graph.py)。

## 6. 同一主脑，行动与相处都有下文

原生Harness工具回执进入同一主脑的对话链。持久收件箱吸收连续未读，生成中的补话可以重整草稿；已执行的工具效果继续保留。后台job通过完成事件衔接，长任务用持久协议分批续做。

outbox区分prepared、sending、sent和unknown，逐段确认。兴趣卡保存动机、进展和下一步；随笔有版本，分享关联精确版本与整条送达回执。自主活动支持自选目标、换向、休息、预约唤醒和聊天后恢复。

实现：[收件箱](../src/warmagent/runtime_inbox.py)、[主脑工具链](../src/warmagent/reading_conversation.py)、[执行账本](../src/warmagent/direct_harness.py)、[活动](../src/warmagent/activities.py)、[私人随笔](../src/warmagent/personal_space.py)。

## 7. 性能结果与复现

README列出的性能数字来自2026-10-28三轮离线合成对照均值，公开的是匿名聚合结果与复现代码。档案规模为1600记录/16个manifest；严格组合包含快照、3次单条读取和10%类型读取；投递规模为50000条记录，其中500条prepared；图规模为2400×96、单线程。档案每轮操作取3次均值，SQL和图预热后各测3轮。

固定只读阶段921.59→155.58ms，待发查询8.145→1.319ms，严格单条读取170.26→137.32ms，精确图672.55→584.31ms。这些局部路径分别对应阶段复用、SQL部分索引、选择性复制和精确计算复用。

复现：`Run-Perf.cmd`；单项入口：[archive](../benchmarks/perf_archive_lab.py)、[database](../benchmarks/perf_database_lab.py)、[graph](../benchmarks/perf_graph_lab.py)。基线源码随仓提供，原始运行输出保存在部署者本地。
